# Ориентация текстового кропа: 0° или 180°

Классификатор для кропов, найденных детектором текста: выдаёт `p_180` — вероятность того, что
кроп перевёрнут на 180°. Метрика — `1 − Brier Score`.

**Результат на тестовой выборке: `1 − Brier = 0.95935`.**

Ансамбль из двух собственных свёрточных сетей, **46 018 параметров суммарно (0.17 МБ)**,
20 000 кропов обрабатываются за ~20 секунд на GPU и ~40 на CPU.

Описание подхода — в первой ячейке [`solution.ipynb`](solution.ipynb).

## Быстрый старт: получить `submission.csv`

Обучающих данных для этого не нужно — веса лежат в репозитории.

```bash
git clone https://github.com/nalivo4ka/avito-cv
cd AvitoCV
pip install -e .
```

Положите тестовые кропы в `test/images/` — 20 000 файлов вида `test_00000.png`:

```
AvitoCV/
├── test/
│   └── images/
│       ├── test_00000.png
│       ├── test_00001.png
│       └── ...
└── solution.ipynb
```

Дальше любым из двух способов.

**Ноутбук** (рекомендуемый — там же описание подхода):

```bash
jupyter notebook solution.ipynb   # выполнить все ячейки
```

**Командой** — аргументы не нужны, значения по умолчанию воспроизводят отправленный файл:

```bash
python scripts/predict.py
```

Оба способа записывают `submission.csv` в корень и дают **побитово одинаковый** файл: весь
инференс детерминирован, сид зафиксирован, окно обрезки не использует случайность. Проверено
четырьмя независимыми запусками в отдельных процессах.

**Про устройство.** Отправленный `submission.csv` получен на видеокарте (CUDA, RTX 2060).
Скрипт сам выбирает GPU, если он есть, иначе считает на процессоре — результат тот же с
точностью до шестого знака: CPU и CUDA складывают числа в разном порядке, и значения на границе
округления `%.6f` расходятся на единицу последнего разряда. На нашем прогоне так разошлись 713
строк из 20 000, **ни одно предсказание не сменило сторону**, сдвиг балла не превышает `7·10⁻⁸`.
Принудительно выбрать устройство можно флагом `--device cuda` или `--device cpu`.

## Полное воспроизведение с нуля

Ниже — вся цепочка от пустого каталога до обученной модели. Занимает около 4 часов,
из них примерно 2.5 — скачивание данных.

```bash
pip install -e ".[data,dev]"
```

### 1. Профиль тестовой выборки

```bash
python scripts/profile_test_set.py --images-dir test/images
```

Измеряет распределения высоты, пропорций, резкости и контраста тестовых кропов и пишет
`configs/test_profile.json`. **Пиксели теста дальше нигде не используются — только эти
распределения.** Утечкой это не является: поворот на 180° не меняет ни ширину кропа, ни высоту,
поэтому извлечь из геометрии метку нельзя даже в принципе.

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--images-dir` | `test/images` | каталог с тестовыми PNG |
| `--output` | `configs/test_profile.json` | куда писать профиль |
| `--sample-size` | `0` | сколько кропов измерить, 0 — все |
| `--seed` | `0` | сид подвыборки |

### 2. Шрифты

```bash
python scripts/collect_fonts.py --variants-per-family 3
```

Скачивает шрифты Google Fonts (OFL 1.1 / Apache 2.0): все семейства с кириллицей, 80 самых
популярных латинских и **все декоративные и рукописные** (`Display`, `Handwriting`). Последние
добавлены прицельно: на тесте труднее всего давались рисованные надписи, где ломаются
типографские закономерности, на которые опирается модель.

Каждый шрифт проходит пробную отрисовку — среди полутора тысяч попадаются экземпляры с
изломанными контурами, которые валят FreeType. Получается ~1 700 пригодных файлов и
`data/fonts/index.json` с покрытием кодпоинтов.

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--output-dir` | `data/fonts/google` | куда класть TTF |
| `--index-path` | `data/fonts/index.json` | индекс с покрытием символов |
| `--lock-path` | `data/fonts/fonts.lock.json` | URL и SHA-256 каждого файла |
| `--cyrillic-families` | `0` | сколько кириллических семейств, 0 — все |
| `--latin-families` | `80` | сколько латинских семейств по популярности |
| `--decorative-families` | `0` | декоративные и рукописные сверх основного отбора, 0 — все |
| `--variants-per-family` | `2` | начертаний на семейство |
| `--workers` | `8` | потоков скачивания |

### 3. Текстовые корпуса

```bash
python scripts/build_corpus.py
```

Русский и английский текст из Wikipedia (CC BY-SA 4.0). Шарды читаются **частично**, HTTP
range-запросами к parquet: скачиваются только те row groups, из которых набирается нужное число
строк — десятки мегабайт вместо трёхсот.

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--output-dir` | `data/corpus` | куда класть `ru.txt` и `en.txt` |
| `--russian-lines` | `600000` | строк русского текста |
| `--english-lines` | `200000` | строк английского текста |
| `--seed` | `0` | сид отбора строк |

### 4. Реальные фотографии

**HierText** (CC BY-SA 4.0) — строчная разметка, 10 005 снимков. Валидационный сплит идёт в
метрику, обучающий — в обучение; они строго не пересекаются.

```bash
python scripts/build_hiertext_manifest.py --split validation            # 42 372 кропа, метрика
python scripts/build_hiertext_manifest.py --split train --no-weights    # 208 108 кропов, обучение
```

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--split` | `validation` | `validation` или `train` |
| `--root` | `data/real/hiertext` | куда скачивать аннотации и снимки |
| `--manifest` | по сплиту | куда писать манифест |
| `--reference-profile` | `configs/test_profile.json` | профиль, под который выравнивается геометрия |
| `--min-height` | `12` | минимальная высота бокса в пикселях |
| `--no-weights` | флаг | не считать веса — так собирается обучающий сплит |

**TextOCR** (CC BY 4.0) — словная разметка, 25 119 снимков. Слова одного снимка склеиваются в
строки: тест приходит от детектора строк, а словный кроп с ним не совпадает по геометрии
(медиана пропорций 2.05 против 4.90). Склейка поднимает её до 3.79 и даёт 781 655 кропов.

```bash
python scripts/build_textocr_manifest.py
```

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--root` | `data/real/textocr` | куда скачивать (архив снимков ~7 ГБ) |
| `--exclude-from` | `data/real/hiertext/validation.jsonl.gz` | разметка, снимки которой нельзя брать в обучение |
| `--min-height` | `12` | минимальная высота бокса |
| `--min-aspect` | `1.0` | минимальные пропорции |
| `--words-only` | флаг | не склеивать слова в строки |
| `--max-run-length` | `3` | сколько подряд идущих слов даёт отдельный кроп помимо строки целиком |
| `--skip-hashes` | флаг | не считать SHA-256 семигигабайтного архива |

**Важно:** оба датасета выросли из Open Images, и 26 снимков TextOCR лежат в валидации
HierText. Скрипт их исключает — без этого одна фотография попала бы и в обучение, и в метрику.

**Кириллические наборы для валидации** — номерные знаки и рукопись:

```bash
python scripts/build_cyrillic_validation.py
```

**Фоны** — 4 000 патчей без текста, вырезанных из снимков HierText по их же разметке (строки
используются как препятствия). Нужны, чтобы под синтетическим текстом была настоящая текстура:

```bash
python scripts/extract_backgrounds.py
```

### 5. Материализация кропов в шарды

```bash
python scripts/materialize_dataset.py --count 600000 --output-dir data/generated/train
python scripts/materialize_dataset.py --count 20000  --output-dir data/generated/val --seed 4321
python scripts/materialize_dataset.py --manifest data/real/train_manifest.parquet \
    --output-dir data/generated/real   --count 250000
python scripts/materialize_dataset.py --manifest data/real/textocr_manifest.parquet \
    --output-dir data/generated/textocr --count 800000
```

Кропы складываются в шарды по 512 МБ (склеенные JPEG плюс parquet-индекс), а не в отдельные
файлы: миллионы мелких файлов на NTFS читаются на порядок медленнее. Индекс сохраняется по ходу
дела каждые 50 000 кропов — генерация идёт около часа, и без этого одна ошибка в конце оставила
бы гигабайты шардов без индекса.

Реальные кропы тоже раскладываются по шардам, а не читаются из манифеста на лету: в манифесте
записи идут подряд по снимкам, и загрузчик с перемешиванием обнулял бы кэш распакованных
изображений.

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--manifest` | — | манифест реальных кропов; без него генерируется синтетика |
| `--slice` | — | взять только один срез манифеста |
| `--output-dir` | `data/generated/train` | каталог хранилища |
| `--count` | `500000` | сколько кропов |
| `--seed` | `2024` | сид генерации |
| `--quality` | `88` | качество JPEG в хранилище |
| `--workers` | `8` | процессов |
| `--shard-size-mb` | `512` | размер шарда |

### 6. Обучение

Две модели ансамбля обучаются одинаковыми командами, отличаются только архитектурой:

```bash
python scripts/train_interactive.py --architecture tiny_tall --input-height 48 \
    --real-store data/generated/real --real-store data/generated/textocr \
    --real-share 0.6 --epochs 12 --run-name tall_v2

python scripts/train_interactive.py --architecture tiny --input-height 48 \
    --real-store data/generated/real --real-store data/generated/textocr \
    --real-share 0.6 --epochs 12 --run-name tiny_v2
```

Каждый прогон — около 25 минут на RTX 2060. Обучение **прерываемое**: `Ctrl+C` сохраняет
состояние, та же команда без `--restart` продолжает ровно с того места — включая моменты Adam,
позицию расписания скорости обучения и сдвиг окна по хранилищам.

| аргумент | по умолчанию | назначение |
|---|---|---|
| `--store` | `data/generated/train` | хранилище синтетики; без него генерация на лету |
| `--real-store` | `data/generated/real` | хранилище реальных кропов; можно повторять, доля делится поровну |
| `--real-share` | `0.5` | доля реальных кропов в эпохе |
| `--no-height-match` | флаг | не выравнивать геометрию реальных кропов под тестовую |
| `--architecture` | `tiny` | `tiny`, `tiny_tall`, `tiny_mean`, `tiny_dense` |
| `--run-name` | по архитектуре | каталог прогона в `artifacts/` |
| `--epochs` | `8` | эпох |
| `--batch-size` | `256` | размер батча |
| `--learning-rate` | `3e-3` | скорость обучения |
| `--input-height` | из конфига | высота входа сети |
| `--eval-limit` | `6000` | кропов на срез при оценке, 0 — весь срез |
| `--seed` | `0` | сид |
| `--restart` | флаг | начать заново, забыв сохранённое состояние |

**Осторожно с `--eval-limit`.** Оценка во время обучения идёт по подвыборке ради скорости, и при
взвешивании под тестовую геометрию её эффективный размер падает до сотен кропов. Она завышала
балл на 0.015. Сравнивать модели надо на полных срезах — следующим скриптом.

### 7. Сравнение моделей и ансамбля

```bash
python scripts/compare_models.py \
    --model tall_v2:artifacts/tall_v2/best.pt:48:4 \
    --model tiny_v2:artifacts/tiny_v2/best.pt:48:8
```

Считает баллы по всем срезам целиком, **калибруя температуру на одной половине среза и меряя
метрику на другой** — иначе каждая модель получает маленькую фору, и разную. При двух и более
моделях добавляет строку ансамбля.

Формат записи модели: `имя:путь:высота_входа:вертикальное_прореживание`.

### 8. Диагностика

```bash
python scripts/diagnose.py --input-height 48
```

Разложение Brier по Мёрфи (надёжность − разрешение + неопределённость) и разбивка баллов по
высоте и пропорциям кропа — чтобы видеть, где именно сидят потери, а не только их сумму.

```bash
python scripts/compare_profiles.py --store data/generated/train
```

Поквантильное сравнение геометрии и резкости сгенерированных кропов с тестовыми.

## Тесты

```bash
pytest
```

205 тестов, ~50 секунд. Ключевые проверяют инварианты, которые легко сломать незаметно:

- **граница поворота** — кроп с меткой 1 обязан быть точным поворотом кропа с меткой 0, а
  кодековые деградации не должны сдвигать статистику между классами. Нарушение этого даёт
  утечку метки, при которой валидация выглядит прекрасно, а тест — случайно;
- **антисимметрия предсказания** — `p(x) + p(rot180 x) = 1` выполняется тождественно;
- **выравнивание геометрии** — сетка накрывает объединение диапазонов, иначе кроп, которого в
  тесте быть не может, унаследовал бы плотность крайней корзины;
- **ограничение растра при отрисовке** — обрезка строки гарантирует, что PIL не попытается
  выделить гигантскую маску (дважды роняло часовую генерацию);
- **возобновление обучения** — моменты оптимизатора и позиция расписания переживают перезапуск.

## Источники данных и лицензии

| источник | что берём | лицензия |
|---|---|---|
| [Google Fonts](https://fonts.google.com) | ~1 700 шрифтов | OFL 1.1 / Apache 2.0 |
| [wikimedia/wikipedia](https://huggingface.co/datasets/wikimedia/wikipedia) | 800 000 строк текста | CC BY-SA 4.0 |
| [HierText](https://github.com/google-research-datasets/hiertext) | 250 480 строчных кропов | CC BY-SA 4.0 |
| [TextOCR](https://textvqa.org/textocr/) | 781 655 словных кропов | CC BY 4.0 |
| тестовая выборка задачи | только распределения высоты и пропорций | — |

Каждый скрипт скачивания пишет lock-файл со списком URL и SHA-256 всех полученных артефактов
(`data/*/*.lock.json`), поэтому набор данных проверяем на совпадение с тем, на котором
обучались отправленные веса.

Использованные приёмы: усечённое importance-семплирование (Ionides, 2008), калибровка
температурой (Guo et al., 2017), разложение Brier по Мёрфи (Murphy, 1973), разделимые свёртки
(Howard et al., 2017).
